# General

## Keep code comments necessary and self-contained

Write comments only for non-obvious constraints, tradeoffs, workarounds, or behavior the code cannot express. Remove empty, narrative, and code-restating comments; preserve PHPDoc needed for types or static analysis. Explain the reason directly instead of citing internal decision numbers or documentation files.

## Keep commit messages concise and human

Use a concise imperative subject. Add a short body only when it clarifies non-obvious motivation, tradeoffs, or verification; avoid verbose AI-style summaries, boilerplate, and AI attribution.
